# 交易决策空计划修复设计

## 问题概述

任务 `a49fd48d-40eb-4f6e-b014-5f6355aee3ef` 中，研究经理收到 HTTP 200 但正文为空，空内容被直接写入 `investment_plan`。交易员随后仅引用该空计划，未把已生成的市场、基本面、情绪和新闻报告作为模型输入，最终生成“缺少决策依据”的兜底提示。风险经理还读取了错误的计划字段，进一步丢失交易员输出。

## 修复设计

1. 研究经理对模型响应做非空和最小长度校验，最多调用三次；记录 `finish_reason`、token 用量等非敏感元数据。三次均无有效内容时抛出明确异常，阻止空报告被当作成功结果。
2. 交易员继续以研究经理计划为主，同时把市场、基本面、情绪和新闻报告显式加入模型消息，避免单点输入缺失。
3. 风险经理优先读取 `trader_investment_plan`，兼容回退到旧字段 `investment_plan`。
4. 股票数据补同步根据数据源能力调用财务同步：Tushare 可传 `limit`，AKShare 仅传 `symbols`。
5. 通过图节点异常保证空投资计划不会进入正常保存链路，不修改已有用户改动的分析服务。

## 兼容性与观测性

- 保留现有状态字段和提示词结构，不改变正常有效响应的业务含义。
- 重试日志不记录提示词、密钥或完整响应，只记录尝试次数、响应长度、结束原因和 token 统计。
- 风险经理保留旧字段回退，兼容历史调用方和旧状态数据。
