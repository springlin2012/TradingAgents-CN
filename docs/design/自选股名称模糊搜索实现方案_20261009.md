# 自选股名称模糊搜索实现方案

> 日期：2026-10-09  
> 状态：设计草案，尚未实施  
> 范围：用户已明确本次只支持 A股。

## 一、目标与现状

在“我的自选股 → 添加自选股”弹窗中，输入股票名称片段，在名称输入框下方展示相关 A股候选列表；点击或通过键盘选中后，同时填充股票名称和六位股票代码。

已先阅读 `docs/TradingAgents-CN项目知识库.md`，并通过 Understand 图谱定位、当前源码核对以下现状：

| 位置 | 当前行为 | 设计依据 |
| --- | --- | --- |
| `frontend/src/views/Favorites/index.vue:251` | 名称使用普通 `el-input` | 替换为 A股名称自动补全输入框 |
| 同文件 `fetchStockInfo:906` | A股代码失焦，调用基础信息接口并写入名称 | 保留入口，增加过期响应校验 |
| `app/routers/stock_data.py:203` | `/api/stock-data/search` 支持名称正则搜索，只查询首选数据源 | 复用接口，增加用于自动补全的兼容模式 |
| `app/services/stock_data_service.py:33` | 基础信息查询兼容 `symbol/code`，优先 `tushare → multi_source → akshare → baostock` | 新搜索模式采用相同来源优先顺序 |
| `app/routers/favorites.py:70` | 已能接收代码、名称、市场、标签、备注 | 新交互仍通过现有添加接口提交 |

以上为静态源码确认；没有连接运行环境验证库中股票覆盖率或响应时间。Understand 图谱中文摘要存在乱码，建议后续运行 `$understand --language zh` 更新；本方案不依赖其摘要作结论。

## 二、方案比较与推荐

| 方案 | 优点 | 代价与限制 |
| --- | --- | --- |
| **推荐：A股自动补全 + 完善已有 A股搜索接口** | 适合现有弹窗，兼容旧查名链路，可解决来源缺失和重复记录 | 需要少量前后端调整 |
| 仅前端接入现有 `/api/stock-data/search` | 改动最少 | 首选来源无数据时漏搜；不解决去重、排序和特殊字符问题 |
| 接入 `MultiMarketStockSearch` 与多市场搜索接口 | 多市场能力已存在 | 当前组件带独立市场选择器和结果区，不适合名称字段；统一搜索还有仅按 `code` 去重和全量取回匹配记录的问题 |

本次采用推荐方案。名称搜索只读 MongoDB `stock_basic_info`，不在每次输入时调用 Tushare、AKShare 或其他外部行情服务。只实现名称子串匹配，不加入拼音、错别字纠正或历史名称别名。

## 三、交互设计

1. 保持截图中的字段顺序和弹窗宽度；A股名称字段使用 Element Plus `el-autocomplete`，港股、美股仍使用普通输入框。
2. 提示改为“输入股票名称搜索，如：海尔、平安”。至少输入一个非空字符；支持中文输入法，组合输入完成后才搜索。
3. 停止输入约 300 毫秒发起一次搜索，每次最多展示 10 条候选。由组件或逻辑层中的一处负责防抖，避免叠加两次延迟。
4. 候选显示“股票名称　股票代码”，例如“海尔智家　600690”；列表与输入框等宽，超过约 240 像素时滚动。使用文本插槽渲染，避免将用户关键词作为 HTML 注入。
5. 支持鼠标点击、上下键、回车选择、Esc 收起。搜索状态、无结果和失败提示放在输入框附近；提示行不能作为候选被选中。未输入时不展示整库列表。
6. 选中候选后，一次写入名称和代码，收起列表，清除两字段之前的校验错误；不触发新一轮名称搜索，也不再为同一候选查一次基础信息。
7. 选中后修改或清空名称，清除此次选择自动填入的代码和选择状态，避免“新名称 + 旧代码”提交。若此前代码由用户手动输入，则保留代码，仍按原手动流程使用。
8. 手动修改代码时清除选择状态及之前自动填入的名称；合法六位代码失焦后继续使用原查名入口。旧请求不能覆盖之后的名称编辑或候选选择。
9. 切换市场、关闭弹窗、重新打开弹窗时，清除候选、状态、计时器并使正在进行的请求失效；标签、备注按现有规则处理。
10. 无结果提示“未找到匹配股票，可输入完整代码和名称”。查询失败提示“搜索暂时不可用，可手动填写”。保留完整代码与名称的手动添加方式；重复添加仍由现有后端检查兜底。

## 四、接口与数据设计

复用现有路径，为新交互增加可选模式参数：

```http
GET /api/stock-data/search?keyword=海&limit=10&mode=autocomplete
```

- `mode`：`default` 或 `autocomplete`，默认 `default`。默认模式保持当前搜索行为，避免静默改变原调用方的数据源策略。
- 自动补全模式：去除关键词首尾空格，空值返回 HTTP 422，长度限制为 50 个字符；`limit` 沿用接口现有 1～50 范围，前端固定传 10。
- 沿用登录鉴权和现有响应层级，`data` 为数组，`total` 为此次返回条数，不表示全库匹配总数。
- 候选必备字段为 `symbol`、`name`、`source`；可保留其他现有标准化字段。代码始终使用六位数字字符串，不转为数字，不提交带交易所后缀的 `full_symbol`。
- 自动补全模式顶层 `source` 使用 `mixed` 表示可能有多个来源；每条记录的实际来源由记录内 `source` 表示。默认模式顶层 `source` 保持原含义。

响应示例，仅说明格式：

```json
{
  "success": true,
  "data": [{"symbol": "600690", "name": "海尔智家", "source": "tushare"}],
  "total": 1,
  "keyword": "海",
  "source": "mixed",
  "message": "搜索完成"
}
```

自动补全搜索逻辑放入 `StockDataService.search_stock_candidates()`，路由只处理参数、鉴权与响应封装：

1. 使用 `re.escape()` 转义关键词，按名称作大小写不敏感的字面子串匹配；`.*`、括号等不会变成正则指令。
2. 读取 A股基础信息集合中的匹配记录，兼容 `symbol` 和 `code`。名称为空、代码无法规范为六位数字的记录不进入候选。
3. 按规范代码去重；同一股票的匹配记录按 `tushare → multi_source → akshare → baostock → 其他/旧记录` 选择来源。未知来源排在已知来源之后；相同来源优先最新更新时间，再以数据库记录标识稳定排序。
4. 候选排序为“名称完全一致 → 名称以关键词开头 → 名称包含关键词”，同等级按股票代码升序，保证结果稳定。
5. 在 MongoDB 聚合中完成字段统一、匹配、来源排序、分组、候选排序和最终 `limit`；仅将最终候选取回应用层。不能先截取 10 条原始记录再去重，否则多来源记录会挤占候选数量。
6. 最终返回去除 `_id` 的标准化记录。不同来源名称可能有版本差异，候选以本次匹配结果为准；选中后跳过同代码失焦查名，避免重新覆盖候选名称。

集合已有股票名称索引的创建逻辑，但包含匹配的正则不保证高效利用普通 B-tree 索引。首版不增加新集合或搜索服务；实际库中检查查询耗时与执行计划。目标是在实际数据规模下搜索接口 P95 不超过 300 毫秒，达不到时再根据证据决定优化，不将该目标当成已验证结论。

## 五、前端状态与异步一致性

新增 `frontend/src/api/stockData.ts`，封装类型明确的 `searchStockCandidates(keyword, limit)`，避免在视图里拼搜索 URL。封装 `symbol/name` 字段，不混用多市场 API 的 `code/name` 响应类型。

名称联想逻辑放入 `frontend/src/composables/useStockNameAutocomplete.ts`，负责候选状态、搜索、清理和请求版本；表单写入由 Favorites 页面负责。

- 每次输入变化立即递增请求版本，包括防抖等待期间；请求发出时保存版本、关键词、市场、弹窗会话号。
- 响应只有在版本、关键词、市场、会话都匹配，且弹窗仍打开时才能更新候选、加载或错误状态。旧响应不得清空新结果；旧 `finally` 不得结束新请求的加载状态。
- 接入 `el-autocomplete` 的回调时，过期请求不能再次调用共享候选更新回调；清空列表由最新输入或显式重置负责。
- `fetchStockInfo()` 同样保存代码、名称编辑版本、市场、会话。返回时还需确认代码未变化、名称未编辑、用户未选中另一股票。
- 选择、重置、市场变化和关闭都递增版本并清除计时器。首版通过版本失效保证一致性，不依赖请求取消改造。
- 搜索失败由字段附近统一提示；搜索请求禁用自动重试。现有请求拦截器部分 HTTP 错误分支未遵守 `skipErrorHandler`，实现时限定修正这些分支，使选择静默处理的搜索请求不会重复弹全局错误；登录失效仍按现有鉴权流程处理。

## 七、验收与验证

| 场景 | 预期 |
| --- | --- |
| 输入“海”，选择“海尔智家 600690” | 自动填入完整名称与代码，代码保留字符串格式 |
| 同一股票具有多个来源记录 | 只展示一条，首选来源缺少该股票时仍能使用其他已入库来源 |
| 同一数据集连续查询 | 完全匹配、前缀匹配优先，返回顺序稳定，最多 10 条 |
| 输入 `.*`、括号、空格 | 字面匹配或规范拒绝，不扩大查询、不报正则解析错误 |
| 连续输入、删空、切市场、关闭再打开 | 旧请求不能恢复旧候选、错误提示或加载状态 |
| 选中后修改名称 | 自动填入的旧代码清空，不允许以旧选择状态提交 |
| 代码查名请求途中编辑名称或选择另一股票 | 旧查名响应不能覆盖最新操作 |
| 输入法组合输入、上下键、回车、Esc | 组合输入完成后搜索，键盘操作正常 |
| 无结果或查询失败 | 提示状态清楚，完整代码和名称仍可手动填写 |
| 港股、美股及已有代码查名 | 原入口和原市场行为正常 |
| 完成添加、重复添加 | 正常添加刷新列表；重复项沿用现有后端提示 |

后端使用独立样本测试查询逻辑和接口默认模式兼容性，不依赖真实行情 API。前端当前未配置测试运行脚本，先做浏览器回归及响应乱序模拟，不为本功能引入一整套新测试框架。
