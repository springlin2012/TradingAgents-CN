# TradingAgents-CN 源码部署与启动总结

> 适用环境：Windows PowerShell、本地源码运行模式
> 适用版本：当前工程（v1.0.x）
> 部署方式：源码运行，不使用 Docker；MongoDB、Redis 作为独立基础服务运行。

## 一、服务与端口

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| Vue 前端 | `http://localhost:3000` | 浏览器访问入口 |
| FastAPI 后端 | `http://localhost:8000` | API、SSE、WebSocket |
| MongoDB | `localhost:27017` | 用户、配置和业务数据 |
| Redis | 以 `.env` 中 `REDIS_HOST`、`REDIS_PORT` 为准 | 缓存、队列和会话 |

## 二、首次安装

在项目根目录 `D:\workSpace\TradingAgents-CN` 打开 PowerShell：

```powershell
python --version                 # Python 3.10+
node --version                   # Node.js 18+
uv venv --python 3.10            # 或：python -m venv .venv
.\.venv\Scripts\Activate.ps1
uv pip install -e .              # 安装 pyproject.toml 定义的依赖
cd frontend
npm install
cd ..
```

复制 `.env.example` 为根目录 `.env`，按实际环境填写 MongoDB、Redis、JWT 和模型 API 配置。源码开发模式建议固定数据库范围，避免调试模式自动生成实例数据库：

```env
MONGODB_DATABASE=tradingagentscn
MONGODB_DATABASE_SCOPE=explicit
ALLOW_SHARED_DB_IN_DEBUG=true
REDIS_ENABLED=true
```

确认 MongoDB 与 Redis 已启动后，首次初始化配置和管理员账号：

```powershell
\.venv\Scripts\Activate.ps1
python scripts/import_config_and_create_user.py --host
```

脚本默认创建管理员账号 `admin`，初始密码为 `admin123`。首次登录后应立即修改密码；生产环境不得使用默认密钥或密码。

## 三、日常启动

打开两个 PowerShell 窗口，并都切换到项目根目录。

窗口一启动后端：

```powershell
\.venv\Scripts\Activate.ps1
python -m app
```

窗口二启动前端：

```powershell
cd D:\workSpace\TradingAgents-CN\frontend
npm run dev
```

然后访问 `http://localhost:3000`。Vite 会把 `/api` 请求代理到 `http://localhost:8000`。

## 四、启动验证

```powershell
Test-NetConnection localhost -Port 3000
Test-NetConnection localhost -Port 8000
Invoke-WebRequest http://localhost:8000/api/health
```

后端健康接口应返回成功状态；浏览器可打开 `http://localhost:8000/docs` 查看 API 文档。登录失败时，优先确认 `.env` 的 `MONGODB_DATABASE` 与导入用户所在数据库一致，再重新执行初始化脚本的 `--create-user-only` 模式。

## 五、停止与排障

在运行服务的窗口按 `Ctrl+C` 停止对应服务。端口被占用时：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3000,8000
netstat -ano | findstr ":3000"
netstat -ano | findstr ":8000"
```

查看运行日志：`.local/logs/backend.out.log`、`.local/logs/backend.err.log`、`.local/logs/frontend.out.log`。本流程不执行 Docker 命令；如改用容器部署，应参考 `docs/deployment/docker/` 下的专用文档。
