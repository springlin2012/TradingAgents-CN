# 小程序登录对接设计

> 项目：`niunai-analysis-tools`（牛来股票分析助手）  
> 后端：TradingAgents-CN（FastAPI，`http://127.0.0.1:8000`）  
> 范围：手机号验证码、账号密码、微信一键登录；登录态写入后续 HTTP 请求。  
> 关联代码：小程序 `pages/login`、`pages/loginCode`、`api/auth.js`、`api/request.js`、`utils/auth.js`；后端 `app/routers/auth_db.py`、`app/services/sms_service.py`、`app/services/wechat_auth_service.py`、`app/services/user_service.py`。

---

## 一、要解决的问题

小程序要访问 TradingAgents-CN 的受保护 HTTP 接口，必须先拿到后端签发的 JWT。微信本身不登录你们的业务系统：`wx.login` 只给出一次性 `code`，业务接口认的是 `Authorization: Bearer <access_token>`。

因此登录页不是另做一套账号产品，而是把三种入口统一换成同一套后端 token：

| 入口 | 用户操作 | 实际换票 |
| --- | --- | --- |
| 手机号 | 输入 11 位手机号 → 短信验证码页 | `sms-code` + `login_type=phone` |
| 密码 | 用户名 / 邮箱 / 手机号 + 密码 | `login_type=password`（兼容 Web 端原接口） |
| 微信 | 勾选协议后点微信按钮 | `wx.login` → `login_type=wechat` |

三种方式登录成功后写入同一对 `access_token` / `refresh_token`，后续受保护接口（如分析报告列表）自动带 Bearer。

---

## 二、架构决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 账号体系 | 复用后端 MongoDB `users`，不单独建小程序用户表 | Web 与小程序共用 JWT 与 `/api/auth/me` |
| 登录入口 | 扩展已有 `POST /api/auth/login`，用 `login_type` 区分 | 前端 Web 仍可只传 `username/password`，无需改旧调用 |
| 短信验证码 | 独立 `POST /api/auth/sms-code`，校验在 login 时完成 | 发送与提交拆开，避免登录时重复发码 |
| 微信换票 | 服务端调 `jscode2session` | AppSecret 不得进小程序 |
| 新用户 | 手机号 / 微信首次登录自动注册 | 小程序侧保持「未注册即注册」文案 |
| 前端请求 | mock 模式下仅 `/api/auth/*` 打真实后端 | 行情等页面仍可本地演示，登录走真接口 |
| 令牌存储 | `wx.setStorageSync` 存 access / refresh / user | 小程序无 Cookie；短时效 access + refresh 续期 |
| 401 | 先 refresh，失败清会话并跳登录页 | 与 Web 端 axios 拦截器同策略 |

## 三、端到端流程

```
用户点登录
  ├─ 密码 ──► POST /api/auth/login {login_type:password}
  ├─ 手机号 ──► POST /api/auth/sms-code
  │                └─ 验证码页 ──► POST /api/auth/login {login_type:phone}
  └─ 微信 ──► wx.login(code)
                 └─ POST /api/auth/login {login_type:wechat, code, appid}
                          │
                          ▼
              后端校验 → 发 JWT
                          │
                          ▼
         小程序 persistSession(access_token, refresh_token, user)
                          │
                          ▼
         后续 GET/POST 自动带 Authorization: Bearer ...
```

微信链路细节：

1. 小程序只调 `wx.login`，把 `code` 和运行时 `appid`（`wx.getAccountInfoSync().miniProgram.appId`）交给后端。
2. 后端用 `WECHAT_MINI_APPID` + `WECHAT_MINI_SECRET` 调微信 `jscode2session`。
3. 按 `openid`（有则优先 `unionid`）查找用户；没有则自动建号。
4. 返回与密码登录相同的 `{ access_token, refresh_token, expires_in, user }`。

手机号链路细节：

1. 前端校验 `^1[3-9]\d{9}$`，通过后再请求发码。
2. 验证码写入 Redis，TTL 默认 300 秒，同一号码 60 秒内不可重发。
3. DEBUG 未对接短信通道时，固定验证码 `123456`（可用 `SMS_DEBUG_CODE` 覆盖）；响应里仅 DEBUG 返回 `debug_code`。
4. 登录成功后删除 Redis 中的验证码，防止重放。

## 四、接口约定

基址：`config.baseUrl`，开发者工具默认 `http://127.0.0.1:8000`。  
统一响应：`{ success, data, message }`；HTTP 4xx/5xx 时 FastAPI 返回 `{ detail }`，小程序 `request.js` 会抽成 `err.message`。

### 4.1 发送验证码

`POST /api/auth/sms-code`

```json
{ "phone": "13800138000" }
```

成功 `200`：

```json
{
  "success": true,
  "data": {
    "phone": "13800138000",
    "expire_in": 300,
    "resend_in": 60
  },
  "message": "验证码已发送"
}
```

失败：`400` 手机号格式错误；`429` 发送过频；`503` Redis 不可用。

### 4.2 登录

`POST /api/auth/login`

密码（兼容旧 Web）：

```json
{ "username": "admin", "password": "******" }
```

也可显式写 `"login_type": "password"`。`username` 可匹配用户名、邮箱或手机号。

手机号：

```json
{ "login_type": "phone", "phone": "13800138000", "sms_code": "123456" }
```

微信：

```json
{ "login_type": "wechat", "code": "<wx.login code>", "appid": "wx********" }
```

成功 `200`：

```json
{
  "success": true,
  "data": {
    "access_token": "<jwt>",
    "refresh_token": "<jwt>",
    "expires_in": 3600,
    "user": {
      "id": "...",
      "username": "...",
      "email": "...",
      "name": "...",
      "is_admin": false,
      "phone": "13800138000"
    }
  },
  "message": "登录成功"
}
```

### 4.3 会话

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/auth/refresh` | body `{ refresh_token }`，换新的 access / refresh |
| `GET` | `/api/auth/me` | 需 Bearer，个人中心展示 |
| `POST` | `/api/auth/logout` | 需 Bearer；服务端记日志，小程序同时清本地 |

受保护业务接口（例如 `GET /api/reports/list`）一律带：

```
Authorization: Bearer <access_token>
```

## 五、数据模型

MongoDB `users` 在原有账号字段上增加身份键（稀疏唯一索引，兼容存量用户）：

| 字段 | 用途 |
| --- | --- |
| `phone` | 短信登录主键 |
| `wechat_openid` | 当前小程序用户标识 |
| `wechat_unionid` | 开放平台打通后跨端归并 |

自动注册约定：

- 手机号用户：`username = p{phone}`，`email = {phone}@phone.local`
- 微信用户：`username = wx_{openid}`（截断至 50），`email = {openid}@wechat.local`
- 随机 bcrypt 密码占位，避免空密码；这批账号不能靠「猜密码」登录，只能走对应登录方式

JWT `sub` 仍是 `username`，与 Web 端 `get_current_user` 一致。

## 六、小程序实现

### 6.1 页面

| 页面 | 行为 |
| --- | --- |
| `pages/login/login` | 默认手机号；切换密码登录；微信按钮 `bindtap="onWechatLogin"`；必须先勾选协议 |
| `pages/loginCode/loginCode` | 展示已发码手机号；倒计时 60 秒；提交 `sms_code` |
| `pages/my/index` | 有 token 则拉 `/api/auth/me`；无 token / 401 显示「请先登录」 |
| `pages/setting/index` | 「退出登录」调 logout 并清本地，回「我的」 |

### 6.2 模块分层

```
pages/login*          只处理交互与校验
api/auth.js           封装登录 / 发码 / me / logout，成功后 persistSession
api/request.js        统一 wx.request：拼 URL、带 token、解包、401 refresh
utils/auth.js         token 读写、跳登录、登录后 switchTab
```

`request.js` URL 规则：

- `isMock === true` 且路径不是 `/api/auth/*` → 相对路径，走本地 Mock
- 否则 → `baseUrl + url`，打 TradingAgents-CN

真机调试把 `config.js` 的 `baseUrl` 改成电脑局域网 IP，例如 `http://192.168.x.x:8000`。开发者工具已在 `project.private.config.json` 关闭 `urlCheck`，便于直连本机 HTTP。

### 6.3 错误与安全

- 4xx 不自动重试；401 仅对非登录接口尝试一次 refresh
- 登录 / 发码请求 `skipAuth` + `skipAuthError`，避免未登录时被踢回登录页死循环
- 不在日志中打印 `code`、token、验证码
- 微信 `appid` 用运行时值，不写死；与后端 `WECHAT_MINI_APPID` 不一致则拒绝
- QQ / 企业微信按钮仅提示「暂未开放」，避免空点击

## 七、后端配置

写入 TradingAgents-CN `.env`（示例见该仓库 `.env.example`）：

```bash
WECHAT_MINI_APPID=wx671f4769b67cd023
WECHAT_MINI_SECRET=your_miniprogram_secret
SMS_CODE_TTL_SECONDS=300
SMS_SEND_INTERVAL_SECONDS=60
SMS_DEBUG_CODE=123456
```

注意：

- `WECHAT_MINI_SECRET` 只放服务端。未配置时微信登录返回 503「未配置微信小程序登录」。
- 当前工程 AppID 仍是模版公开值 `wx671f4769b67cd023`，正式环境必须换成自有小程序并同步改 `.env`。
- 改完后端代码必须**重启** FastAPI，否则 `/docs` 仍是旧 schema（`username`/`password` 必填，没有 `/sms-code`）。

生产短信：把 `app/services/sms_service.py` 的 `send_login_code` 接到真实通道，并关闭 DEBUG 固定验证码。

## 八、验证清单

1. 重启 TradingAgents-CN，打开 `http://localhost:8000/docs`：应出现 `POST /api/auth/sms-code`，login body 含 `login_type`。
2. 密码：用已有 Web 账号登录小程序，应进入「我的」并显示用户名。
3. 手机号：`13800138000` + `123456`（DEBUG），首次应自动注册。
4. 微信：配置 AppId/Secret 后，开发者工具或真机点微信按钮；H5 预览拿不到真实 `wx.login` code，不能当验收。
5. 带 token 访问 `GET /api/auth/me` 与 `GET /api/reports/list` 应成功；清 token 后业务接口 401 并跳登录。
6. 设置页退出后，「我的」回到未登录态。
