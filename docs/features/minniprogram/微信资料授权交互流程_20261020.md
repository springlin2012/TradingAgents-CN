# 微信资料授权交互流程

> 日期：2026-10-20  
> 页面：`pages/loginProfile/loginProfile`  
> 关联：`docs/design/微信资料授权_20261020.md`

微信不允许登录后静默读取昵称、头像。用户必须在完善资料页**各点一次**官方组件，才会把资料用于展示。内部登录账号 `username`（`wx_{openid}`）全程不变。

---

## 一、总流程

```
点微信登录
  → 后端签发 JWT，username = wx_{openid}
  → 有 nickname？
        有 → 进「我的」，展示昵称
        无 → 进完善资料页
              ├─ 点头像 → 微信选头像 → 立刻上传
              ├─ 点昵称框 → 微信填昵称 → 仅先填在页面上
              ├─ 点「保存并进入」→ 把昵称写入后端 → 进「我的」
              └─ 点「暂不授权」→ 进「我的」，仍显示 wx_...
```

之后也可从「我的 → 完善微信资料」或「去授权微信资料」标签再进入同一页。

---

## 二、步骤说明

### 1. 点微信登录

用户在登录页勾选协议，点微信按钮。小程序只调 `wx.login` 拿 `code`，交给 `POST /api/auth/login`（`login_type=wechat`）。

此时已经登录成功，本地已有 `access_token`。返回的 `user.username` 是 `wx_` 加 openid，`nickname` 为空。

### 2. 决定去哪

`goFillProfileIfNeeded` 看 `user.nickname`：

- 空：`redirectTo` 到完善资料页（替换登录页，避免返回又进登录）
- 已有：`switchTab` 到「我的」

手机号验证码登录若也没有昵称，会走同一页，方便以后统一补资料。

### 3. 完善资料页长什么样

标题「授权微信头像和昵称」。三个可点区域：

| 控件 | 用户动作 | 微信做什么 |
| --- | --- | --- |
| 圆形头像按钮 `open-type="chooseAvatar"` | 点头像 | 弹出选头像（微信头像 / 相册 / 拍摄） |
| 输入框 `type="nickname"` | 点昵称框 | 弹出微信昵称填写，不是普通键盘 |
| 「保存并进入」 | 点主按钮 | 把昵称提交后端 |
| 「暂不授权，稍后再说」 | 点文字按钮 | 跳过，进「我的」 |

头像和昵称是**两次独立授权**，没有「一键全授权」。顺序不限，但保存时必须已经有昵称。

### 4. 点头像

1. 微信弹出头像选择器。  
2. 用户选「用微信头像」或从相册选一张。  
3. 取消则页面不变。  
4. 确认后回调 `onChooseAvatar`，拿到本地临时路径 `avatarUrl`。  
5. 页面立刻换成这张图，并 `wx.uploadFile` 到 `POST /api/auth/avatar`（带 Bearer）。  
6. 后端存到 `uploads/avatars/{用户id}.jpg`，用户表写入 `avatar`。  
7. 上传失败只提示，不退出登录。

头像在这一步就已经落到后端，不必等点保存。

### 5. 点昵称框

1. 用户点「点击填写微信昵称」。  
2. 微信弹出昵称填写面板，可带出当前微信昵称，也可改字。  
3. 取消则输入框仍空。  
4. 确认后 `bindchange` / `bindblur` 把文案写进页面的 `nickname`。  
5. **此时还没有调后端**，只是填在表单里。

不能把普通 `<input>` 当成授权。必须是 `type="nickname"`，否则拿不到微信昵称。

### 6. 点保存并进入

1. 昵称为空：toast「请先点击输入框授权昵称」，留在本页。  
2. 有昵称：`POST /api/auth/profile`，body `{ nickname }`。  
3. 后端只更新 `nickname`，不改 `username`。  
4. 成功后进「我的」。展示名优先 `nickname`，头像用已上传的 `avatar`。

### 7. 点暂不授权

直接进「我的」。登录态保留。展示名仍是 `wx_{openid}`，头像用默认图（除非刚才已经上传过头像）。页面会出现「去授权微信资料」。

### 8. 「我的」页再授权

两条入口进同一完善资料页：

- 资料卡上的「去授权微信资料」（仅 `needProfile` 时显示）
- 列表项「完善微信资料」

已授过权再进，会带出已保存的昵称和头像，可改后再保存。

## 三、页面、接口、字段

| 步骤 | 页面 / 接口 | 写入字段 |
| --- | --- | --- |
| 登录 | `POST /api/auth/login` | `username`、token；`nickname` 仍空 |
| 选头像 | `POST /api/auth/avatar` | `avatar` |
| 保存昵称 | `POST /api/auth/profile` | `nickname` |
| 展示 | `GET /api/auth/me` | `name` = nickname 或 username |

JWT 的 `sub` 始终是内部 `username`。

---

## 四、失败与边界

- 未勾选协议：登录页拦住，进不了授权页。  
- 微信选头像取消：不上传。  
- 头像上传失败：toast，可重试；昵称仍可稍后保存。  
- 未填昵称就保存：拦住。  
- 真机 `baseUrl` 若仍是 `127.0.0.1`：头像上传会失败，需改成电脑局域网 IP。  
- 开发者工具 H5 预览没有 `chooseAvatar` / `type=nickname`，不能当验收。  
- 跳过后再登录：只要库里还没有 `nickname`，仍会进完善资料页。

---

## 五、用户视角一条线（首次）

1. 登录页勾选协议，点微信。  
2. 进入「完善资料」，看到默认头像和空昵称。  
3. 点头像，选微信头像，圆图换成自己的。  
4. 点昵称框，用微信昵称或改几个字。  
5. 点「保存并进入」。  
6. 「我的」显示微信昵称和头像，不再显示 `wx_...`。
