# 项目数据表（MongoDB 集合）汇总

> 更新时间：2026-09-07  
> 适用项目：TradingAgents-CN

## 1. 说明

本项目后端主要使用 MongoDB，代码中的“数据表”对应 MongoDB Collection；没有发现项目自有的 SQL `CREATE TABLE` 或 ORM `__tablename__` 定义。

默认数据库名称由 `MONGO_DB` 配置决定，常见配置名为 `tradingagents`。由于 MongoDB 集合可以按需创建，下面的列表按源码、初始化脚本、导出配置和数据库文档综合整理，分为：

- 当前主流程明确使用的集合；
- 跨市场功能映射或按需创建的集合；
- 旧版、兼容或历史脚本中仍可见的集合。

## 2. 当前主流程集合

### 2.1 股票数据

| 集合名 | 用途 | 典型内容或特点 |
|---|---|---|
| `stock_basic_info` | A 股股票基础信息 | 股票代码、名称、行业、上市日期、估值指标；通过 `code + source` 区分数据源 |
| `market_quotes` | A 股实时行情 | 最新价、开高低、成交量、成交额、涨跌幅等；行情入库任务高频更新 |
| `stock_daily_quotes` | A 股历史 K 线 | 日/周/月等周期的历史行情；常用复合查询键为 `symbol + trade_date + data_source + period` |
| `stock_financial_data` | 股票财务数据 | 财务报表及 ROE、利润率等指标；通常按报告期和数据源查询 |
| `stock_news` | 股票新闻 | 新闻标题、正文、发布时间、关联股票等 |

股票筛选视图 `stock_screening_view` 会把 `stock_basic_info`、`market_quotes` 和最新的 `stock_financial_data` 关联起来，供筛选服务使用。

### 2.2 分析任务与报告

| 集合名 | 用途 | 备注 |
|---|---|---|
| `analysis_batches` | 批量分析批次 | 保存批量分析的批次级状态和元数据 |
| `analysis_tasks` | 分析任务 | 保存任务状态、参数、进度、结果引用等；任务执行期间优先查询此集合 |
| `analysis_reports` | 已完成分析报告 | 当前报告主集合；报告接口和分析服务均使用该名称 |

`analysis_results` 在旧版初始化脚本、清理脚本或诊断脚本中仍可见，但当前报告主流程使用的是 `analysis_reports`，不应将两者混为一谈。

### 2.3 用户、自选股与通知

| 集合名 | 用途 |
|---|---|
| `users` | 用户账号、密码摘要、角色、偏好、配额等 |
| `user_favorites` | 用户自选股及标签/备注；当前服务明确以此为统一存储 |
| `user_tags` | 用户自定义标签 |
| `notifications` | 站内通知及已读/未读状态 |

### 2.4 系统与模型配置

| 集合名 | 用途 |
|---|---|
| `system_configs` | 系统激活配置，包含 LLM、数据源、缓存、任务等配置数组 |
| `llm_providers` | LLM 服务提供商及 API 配置 |
| `model_catalog` | 可用模型目录、价格、能力和上下文信息 |
| `market_categories` | 市场分类，如 A 股、港股、美股 |
| `datasource_groupings` | 数据源分组、启用状态和优先级 |
| `platform_configs` | 平台级配置（导出配置清单中包含） |
| `user_configs` | 用户个性化配置（导出配置清单中包含） |

### 2.5 同步、调度与运维

| 集合名 | 用途 |
|---|---|
| `sync_status` | 股票基础信息、历史数据等同步任务状态 |
| `quotes_ingestion_status` | 实时行情入库任务状态 |
| `scheduler_metadata` | 调度任务定义或调度元数据 |
| `scheduler_executions` | 调度执行实例、状态和结果 |
| `scheduler_history` | 调度历史记录 |
| `operation_logs` | 用户和系统操作日志 |
| `token_usage` | LLM Token 使用量、模型、成本、会话等统计 |
| `internal_messages` | 系统内部消息、有效期、影响范围和可靠性等信息 |
| `social_media_messages` | 社交媒体消息、情绪、互动量和来源等信息 |

### 2.6 模拟交易

| 集合名 | 用途 |
|---|---|
| `paper_accounts` | 模拟交易账户及现金资产 |
| `paper_market_rules` | 模拟交易市场规则 |

| `paper_orders` | 模拟订单 |

## 3. 跨市场集合

统一股票服务在 `app/services/unified_stock_service.py` 中配置了 CN/HK/US 三套集合映射：

| 市场 | 基础信息 | 实时行情 | 历史 K 线 | 财务数据 | 新闻 |
|---|---|---|---|---|---|
| CN | `stock_basic_info` | `market_quotes` | `stock_daily_quotes` | `stock_financial_data` | `stock_news` |
| HK | `stock_basic_info_hk` | `market_quotes_hk` | `stock_daily_quotes_hk` | `stock_financial_data_hk` | `stock_news_hk` |
| US | `stock_basic_info_us` | `market_quotes_us` | `stock_daily_quotes_us` | `stock_financial_data_us` | `stock_news_us` |

目前源码已明确直接读写港股/美股基础信息和行情集合；带 `_hk`/`_us` 后缀的历史、财务、新闻集合属于统一服务的预留/按需集合，是否实际存在应以运行环境的集合统计为准。

## 4. 旧版、兼容或缓存集合

以下名称在旧版文档、初始化脚本、兼容代码或传统缓存实现中出现，不代表当前主流程一定会持续写入：

| 集合名 | 来源或用途说明 |
|---|---|
| `stock_data` | 旧版/传统股票缓存；早期数据库初始化脚本使用 |
| `news_data` | 旧版新闻缓存 |
| `fundamentals_data` | 旧版基本面缓存 |
| `historical_data` | 旧版历史数据或状态检查兼容名称 |
| `financial_data_cache` | 财务数据缓存 |
| `cache` | 自适应缓存实现使用的通用缓存集合 |
| `configurations` | 早期通用配置集合，旧初始化脚本中出现 |
| `user_sessions` | 旧版用户会话集合，清理脚本仍保留兼容逻辑 |
| `login_attempts` | 登录尝试记录，清理脚本仍保留兼容逻辑 |
| `analysis_results` | 旧版分析结果名称；当前报告主集合为 `analysis_reports` |

这些集合如需迁移、清理或删除，必须先确认运行环境和数据备份，不应仅依据历史脚本执行破坏性操作。

## 5. 视图与非 MongoDB 存储

### 5.1 MongoDB 视图

- `stock_screening_view`：基于 `stock_basic_info` 创建，并通过 `$lookup` 关联 `market_quotes` 和 `stock_financial_data`。
- 这是 MongoDB View，不是独立业务数据表，不能按普通集合理解其写入行为。

### 5.2 Redis

Redis 用于缓存和运行时状态，不属于 MongoDB 集合。项目中可见的缓存键包括分析缓存、筛选缓存和数据缓存等，具体键名、TTL 由运行配置决定。

### 5.3 文件型数据

旧版 Web 目录还会在 `data/analysis_results`、`data/logs/operations` 等路径保存报告或日志文件。这些文件目录不属于 MongoDB 数据表，但可能与数据库中的分析任务、报告和操作日志并存。

## 6. 如何查看运行环境中的真实集合

数据库管理接口会直接调用 MongoDB 的 `list_collection_names()` 和 `collStats`：

```text
GET /api/system/database/stats
```

该接口需要登录权限，返回实际集合数量、文档数、存储大小和索引数量。由于 MongoDB 集合可能按需创建，生产环境的实际列表可能少于或多于本文档中的源码清单。
