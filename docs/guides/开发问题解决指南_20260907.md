# TradingAgents-CN 默认登录密码问题解决指南

> 适用范围：TradingAgents-CN 当前 Vue + FastAPI + MongoDB 主应用，以及仓库中保留的旧版 Web/Streamlit 登录模块。
>
> 更新时间：2026-09-07

## 1. 问题现象

常见表现包括：

- 登录页提示“用户名或密码错误”；
- 使用文档中的 `admin / admin123` 无法登录；
- 修改了 `config/admin_password.json`，但主应用登录结果没有变化；
- 运行旧版用户管理脚本后，Vue 前端仍然无法登录。

这类问题通常不是前端输入框故障，而是“实际认证链路”和“被修改的密码存储位置”不一致。

## 2. 先确认当前使用哪条认证链路

| 使用场景 | 实际登录接口/入口 | 密码存储位置 | 修改方式 |
| --- | --- | --- | --- |
| 当前主应用（Vue 前端） | `/api/auth/login` | MongoDB 当前数据库的 `users` 集合 | 设置页面或 MongoDB 定向更新 |
| 旧版 Web/Streamlit | `web/components/login.py` | `web/config/users.json` | `scripts/user_password_manager.py` |

当前主应用的关键源码位置：

- 登录页默认提示：`frontend/src/views/Auth/Login.vue`；
- 路由注册：`app/main.py` 中将认证路由挂载到 `/api/auth`；
- 登录处理：`app/routers/auth_db.py` 的 `login`；
- 密码校验与修改：`app/services/user_service.py` 的 `authenticate_user`、`change_password`；
- 密码哈希：`UserService.hash_password` 使用 SHA-256。

因此，主应用登录时只查询 MongoDB 用户记录，不能把 `config/admin_password.json` 当作唯一密码来源。

## 3. 默认密码的正确理解

- 新部署初始化逻辑通常使用默认管理员 `admin / admin123`；
- 登录页也显示 `admin / admin123`，但这只是默认提示，不代表数据库中一定已经存在该账号；
- `config/admin_password.json` 属于旧初始化兼容逻辑，当前主应用是否读取它取决于具体初始化脚本；
- 文档中出现的 `1234567` 是历史配置说明，不能据此判断当前数据库密码；
- 数据库名由 `.env` 中的 `MONGODB_*` 配置以及 `MONGODB_DATABASE_SCOPE` 共同决定。连接错数据库时，即使密码哈希正确也会登录失败。

## 4. 推荐处理流程

### 4.1 仍能登录：通过页面修改（首选）

1. 登录主应用；
2. 进入 `设置` → `安全设置`；
3. 点击 `修改密码`；
4. 输入当前密码、新密码和确认密码；
5. 修改成功后重新登录。

主应用会先验证旧密码，再更新 MongoDB `users` 集合中的 `hashed_password` 字段。新密码至少 6 位，生产环境建议使用 12 位以上的随机密码。

### 4.2 完全无法登录，但可以连接 MongoDB：定向更新密码

在项目根目录执行以下 PowerShell 命令。命令使用当前 `.env` 的 MongoDB 配置，通过 `getpass` 交互输入新密码，不会把密码写入命令历史：

```powershell
python -c 'import getpass,hashlib; from pymongo import MongoClient; from app.core.config import settings; p=getpass.getpass("新密码: "); db=MongoClient(settings.MONGO_URI)[settings.MONGO_DB]; r=db.users.update_one({"username":"admin"},{"$set":{"hashed_password":hashlib.sha256(p.encode()).hexdigest()}}); print(f"matched={r.matched_count}, modified={r.modified_count}")'
```

结果判断：

- `matched=1, modified=1`：已更新 `admin` 密码，可重新登录；
- `matched=0`：当前生效数据库中没有 `admin` 用户，先核对 `.env` 和实际数据库，再考虑创建管理员；
- `modified=0`：可能输入了与原密码相同的密码，或数据库连接/权限异常。

执行前请确认当前 `.env` 指向的是目标环境，避免误改共享数据库。

### 4.3 当前数据库没有管理员用户：创建管理员

仅在确认目标数据库确实没有 `admin` 用户时执行：

```powershell
python scripts/create_default_admin.py --username admin --password "你的新密码"
```

该脚本会创建新的管理员文档并使用 SHA-256 保存密码。脚本中的 MongoDB 连接参数是独立配置，可能与 `.env` 不同；若连接目标不一致，应先人工核对脚本配置和运行环境。

如果脚本提示用户已存在，不要直接使用 `--overwrite`。该选项会先删除旧用户再重建，可能造成用户属性、关联记录或会话信息丢失；按本项目安全规则，应由具备权限的人工流程确认后处理。

### 4.4 使用旧版 Web/Streamlit 界面

只有在确认实际运行的是旧版 Web 登录时，才使用下面的命令：

```powershell
python scripts/user_password_manager.py change-password admin "你的新密码"
```

该命令修改的是 `web/config/users.json`，不会修改当前 Vue/FastAPI 主应用使用的 MongoDB 用户密码。旧版默认账号通常为 `admin / admin123`，普通用户通常为 `user / user123`。

## 5. 修改后验证

### 5.1 通过主应用接口验证

PowerShell 示例：

```powershell
$body = @{ username = "admin"; password = "你的新密码" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://localhost:8000/api/auth/login" -ContentType "application/json" -Body $body
```

成功时响应中应包含 `success: true` 和 `data.access_token`。如果接口返回 401，继续检查数据库、用户名、密码哈希和连接环境。

### 5.2 检查前端缓存

密码修改成功后，旧 JWT 可能仍保存在浏览器本地存储中。可退出登录后重新打开页面；若页面状态异常，再清理当前站点的本地存储并刷新。不要通过修改前端代码绕过认证。

### 5.3 检查后端日志

重点关注：

- 后端连接的数据库名称是否为预期环境；
- `users` 集合是否能查到 `username=admin`；
- 用户是否为激活状态（`is_active=true`）；
- 登录日志是否显示“用户不存在”还是“密码错误”。

不要在日志、工单或文档中粘贴明文密码、完整 JWT 或完整密码哈希。

## 6. 常见误区与排查顺序

1. **只改 `config/admin_password.json`**：当前主应用通常认证 MongoDB，不会因该文件变化而自动更新已有用户。
2. **把旧 Web 脚本当成主应用脚本**：`user_password_manager.py` 修改的是 JSON 文件，和 MongoDB 用户表不是同一份数据。
3. **连接了错误数据库**：核对 `.env` 的 `MONGODB_HOST`、端口、数据库名、认证源，以及 `MONGODB_DATABASE_SCOPE` 的实际生效值。
4. **管理员用户不存在**：初始化脚本可能只创建配置文件，没有成功写入当前数据库；先检查 `users` 集合，再创建管理员。
5. **运行了覆盖/重置脚本**：覆盖和重置逻辑可能包含删除用户或批量清理数据，存在不可逆风险，不应作为常规排障步骤。
6. **只重启前端**：密码存储在后端数据库，修改后通常不需要重建前端；若后端配置变更，再按部署方式重启后端服务。

## 7. 安全注意事项

- 生产环境首次登录后立即更换默认密码；
- 新密码不要与 MongoDB、Redis、JWT 密钥或操作系统密码复用；
- 不要把真实密码写入脚本、`.env`、Markdown、终端截图或 Git 提交；
- 执行数据库更新前确认主机、数据库名和账号权限，避免误操作共享环境；
- 本指南不包含任何数据库删除、清空、重置或配置中心修改操作。若必须清理或覆盖用户数据，应由具备权限的人工流程审批执行。
