# TradingAgents-CN v1.0.1 启动方式

> 适用版本：`v1.0.1`
> 更新日期：2026-08-27
> 适用系统：Windows、macOS、Linux

本文档结合 [v1.0.1 使用手册](v1.0.1-user-manual.md)，并以仓库当前代码和根目录 `docker-compose.yml` 为准，整理不同系统环境下的启动方式、操作流程和启动后的首次使用步骤。

## 一、启动方式总览

当前共有三种启动方式：

| 启动方式 | 适用场景 | 启动内容 | 推荐度 |
| --- | --- | --- | --- |
| Docker Compose | Windows、macOS、Linux；希望一次启动完整服务 | Vue 前端、FastAPI 后端、MongoDB、Redis | **推荐** |
| 源码开发模式 | 开发、调试、修改前后端代码 | 本机 Vue + FastAPI，MongoDB/Redis 可使用本机服务或 Docker | 开发推荐 |
| 旧版 Streamlit | 兼容历史使用场景 | 旧版 Web 界面，端口 8501 | **过时** |

### 各方式操作流程

1. **Docker Compose**：准备 Docker 和 `.env` → 首次构建并启动 → 检查容器健康状态 → 访问 `http://localhost:3000`。
2. **源码开发模式**：准备 Python、uv、Node.js → 创建虚拟环境并安装项目依赖 → 启动本机或 Docker 中的 MongoDB/Redis → 启动 FastAPI 后端 → 启动 Vue 前端。
3. **旧版 Streamlit**：准备 Python 环境和项目依赖 → 执行 `python web/run_web.py` → 访问 `http://localhost:8501`。该方式不用于当前主架构。

> 同一台机器只建议选择一种 Web 前端方式运行。Docker Compose 的 Vue 前端使用 3000 端口，旧版 Streamlit 使用 8501 端口；源码开发模式的后端和前端分别使用 8000、3000 端口。

## 二、当前服务架构与端口

当前主架构为 FastAPI 后端 + Vue 3 前端，MongoDB 和 Redis 作为基础服务：

| 服务 | Compose 服务名 | 主机端口 | 用途 |
| --- | --- | ---: | --- |
| Vue 前端 | `frontend` | `3000` | 浏览器访问入口 |
| FastAPI 后端 | `backend` | `8000` | REST API、SSE、WebSocket |
| MongoDB | `mongodb` | `27017` | 数据存储 |
| Redis | `redis` | `6379` | 缓存、队列和会话 |
| Redis Commander（可选） | `redis-commander` | `8081` | Redis 管理界面 |
| Mongo Express（可选） | `mongo-express` | `8082` | MongoDB 管理界面 |

启动后访问：

- 前端：http://localhost:3000
- 后端健康检查：http://localhost:8000/api/health
- API 文档（开发模式）：http://localhost:8000/docs

> **端口说明**：使用手册中的“后端 API 默认 `3001`”是通用部署示例；当前仓库 `app/core/config.py` 和根目录 Compose 配置默认使用 `8000`。如果在 `.env` 中修改了 `HOST` 或 `PORT`，请以实际配置和启动日志为准。

## 三、启动前准备

### 3.1 通用要求

- Docker Desktop（Windows、macOS）或 Docker Engine + Compose 插件（Linux）。
- Python 3.10 或更高版本（源码开发模式需要，版本约束以 `pyproject.toml` 为准）。
- `uv`（推荐的 Python 项目和依赖管理工具；源码开发模式需要）。
- Node.js 18 或更高版本、npm 8 或更高版本（前端源码开发需要）。
- 至少一个大模型 API Key，例如 `DEEPSEEK_API_KEY` 或 `DASHSCOPE_API_KEY`。

### 3.2 创建并编辑 `.env`

Windows PowerShell：

```powershell
cd D:\workSpace\TradingAgents-CN
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

macOS/Linux：

```bash
cd /path/to/TradingAgents-CN
if [ ! -f .env ]; then cp .env.example .env; fi
nano .env
```

至少确认以下配置已填写并使用安全值：

```env
JWT_SECRET=请替换为随机字符串
DEEPSEEK_API_KEY=你的API密钥
```

如果使用其他模型提供商，可改为配置 `DASHSCOPE_API_KEY`、`OPENAI_API_KEY` 等。不要把真实密钥提交到 Git。

## 四、Docker Compose 启动（推荐）

Docker 方式适合 Windows、macOS 和 Linux，三种系统使用同一套 Compose 配置。

### 4.1 检查 Docker

```bash
docker --version
docker compose version
```

Windows 用户需要先启动 Docker Desktop；Linux 用户需要确保 Docker 服务已启动并且当前用户有执行 Docker 的权限。

### 4.2 首次启动或代码变更后

Windows PowerShell、macOS、Linux 均可执行：

```bash
docker compose up -d --build
```

该命令会构建后端和前端镜像，并启动 MongoDB、Redis 及应用服务。首次构建可能需要数分钟。

### 4.3 日常启动

镜像已构建且没有修改代码或依赖时：

```bash
docker compose up -d
```

### 4.4 查看状态与日志

```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
```

浏览器打开 http://localhost:3000；如果页面无法访问，先确认 `backend`、`frontend`、`mongodb`、`redis` 均处于 `Up` 或健康状态。

### 4.5 启用可选管理界面

```bash
docker compose --profile management up -d
```

然后访问：

- Redis Commander：http://localhost:8081
- Mongo Express：http://localhost:8082

### 4.6 停止或重启

```bash
# 停止容器但保留容器和数据卷
docker compose stop

# 重新启动
docker compose restart
```

## 五、源码开发模式

源码开发模式需要本机安装 Python 和 Node.js。MongoDB、Redis 可以使用 Docker 启动，也可以安装为本机服务；两种方式二选一即可。源码后端运行在本机时，数据库地址应使用 `localhost`，不能使用 Docker 容器内部的主机名 `mongodb` 或 `redis`。

### 5.1 选择并启动 MongoDB 和 Redis

#### 5.1.1 方案 A：使用 Docker 启动基础服务（可选）

在项目根目录执行（Windows、macOS、Linux 相同）：

```bash
docker compose up -d mongodb redis
```

该命令只启动 MongoDB 和 Redis，不会启动 Docker 版后端或前端。服务对本机映射的端口为 MongoDB `27017`、Redis `6379`。

#### 5.1.2 方案 B：使用本机服务（非 Docker）

如果已在操作系统中安装 MongoDB 和 Redis，则不执行上一节的 Docker 命令，直接启动本机服务。

**Windows**

MongoDB 安装为 Windows 服务时：

```powershell
Get-Service MongoDB
Start-Service MongoDB
Set-Service MongoDB -StartupType Automatic
```

如果 MongoDB 没有安装为服务，可手动启动（`mongod` 已加入 `PATH`）：

```powershell
New-Item -ItemType Directory -Force C:\data\db
mongod --dbpath C:\data\db --bind_ip 127.0.0.1 --port 27017
```

Redis 官方没有持续维护的原生 Windows 版本。Windows 建议使用 Memurai，或在 WSL2 的 Ubuntu 中安装 Redis。

使用 Memurai 服务：

```powershell
Get-Service Memurai
Start-Service Memurai
```

使用 WSL2 Ubuntu：

```bash
sudo apt update
sudo apt install redis-server
sudo service redis-server start
```

**macOS**

使用 Homebrew 安装并启动：

```bash
brew tap mongodb/brew
brew install mongodb-community
brew install redis

brew services start mongodb-community
brew services start redis
```

**Linux**

安装 MongoDB 官方软件包后，启动服务：

```bash
sudo systemctl enable --now mongod
sudo systemctl status mongod
```

安装 Redis 后，启动服务：

```bash
sudo apt install redis-server
sudo systemctl enable --now redis-server
sudo systemctl status redis-server
```

不同 Linux 发行版的软件包名称可能不同；如果服务名不是 `mongod` 或 `redis-server`，以发行版实际安装的服务名为准。

#### 5.1.3 本机服务认证与连接配置

`.env.example` 默认填写了 MongoDB 用户 `admin`、密码 `tradingagents123`，以及 Redis 密码 `tradingagents123`。本机服务必须与这些配置保持一致，否则请修改 `.env`。

如果本机 MongoDB、Redis 均未启用密码认证，可在 `.env` 中清空认证字段：

```env
MONGODB_HOST=localhost
MONGODB_PORT=27017
MONGODB_USERNAME=
MONGODB_PASSWORD=

REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=
REDIS_DB=0
```

如果需要沿用示例中的认证配置：

1. 在 MongoDB 的 `admin` 数据库中创建 `admin` 用户，并按安装版本在 `mongod.conf` 中启用 `security.authorization: enabled`，然后重启 MongoDB。

   ```javascript
   mongosh
   use admin
   db.createUser({
     user: "admin",
     pwd: "tradingagents123",
     roles: [{ role: "root", db: "admin" }]
   })
   ```

2. 在 Redis 配置文件中设置 `requirepass tradingagents123`，然后重启 Redis 或 Memurai。

验证本机服务：

```bash
# MongoDB（未启用密码）
mongosh --host 127.0.0.1 --port 27017 --eval "db.runCommand({ ping: 1 })"

# MongoDB（已启用密码）
mongosh --host 127.0.0.1 --port 27017 -u admin -p --authenticationDatabase admin --eval "db.runCommand({ ping: 1 })"

# Redis/Memurai（未启用密码）
redis-cli -h 127.0.0.1 -p 6379 ping

# Redis/Memurai（已启用密码）
redis-cli -h 127.0.0.1 -p 6379 -a tradingagents123 ping
```

Windows 使用 Memurai 时，可将 `redis-cli` 替换为 `memurai-cli`；WSL2、macOS 和 Linux 使用 `redis-cli`。

MongoDB 返回 `ok: 1`、Redis 返回 `PONG` 后，再继续创建 Python 环境、启动后端和启动前端。非 Docker 源码开发的完整顺序为：启动本机 MongoDB → 启动本机 Redis → `python -m app.main` → `cd frontend && npm run dev`。

### 5.2 安装 uv 并创建 Python 虚拟环境

当前项目以 `pyproject.toml` 作为 Python 依赖的事实来源。仓库根目录的 `requirements.txt` 已标注为弃用文件，不应再作为 v1.0.1 的安装入口。

Windows PowerShell 安装 uv：

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://astral.sh/uv/install.ps1 | iex"
uv --version
```

macOS/Linux 安装 uv：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version
```

如果系统无法使用安装脚本，也可以先用 pip 安装 uv：

```bash
python -m pip install uv
```

创建虚拟环境（推荐使用 `uv`）：

Windows PowerShell：

```powershell
cd D:\workSpace\TradingAgents-CN
uv venv --python 3.10
.\.venv\Scripts\Activate.ps1
```

Windows 命令提示符（cmd）：

```bat
cd /d D:\workSpace\TradingAgents-CN
uv venv --python 3.10
.venv\Scripts\activate.bat
```

macOS/Linux：

```bash
cd /path/to/TradingAgents-CN
uv venv --python 3.10
source .venv/bin/activate
```

如果 PowerShell 阻止脚本执行，可仅对当前窗口放宽策略：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

如果不使用 uv，可用 Python 标准库创建环境：`python -m venv .venv`（Windows 激活 `.venv\Scripts\Activate.ps1`，macOS/Linux 激活 `source .venv/bin/activate`）。

### 5.3 安装 Python 依赖

激活虚拟环境后，在项目根目录执行：

```bash
# 推荐：从 pyproject.toml 安装当前项目及其依赖
uv pip install -e .
```

如果不使用 uv，可使用标准 pip 读取同一个 `pyproject.toml`：

```bash
python -m pip install -e .
```

安装完成后验证：

```bash
python -c "import tradingagents; print('TradingAgents-CN 依赖安装成功')"
```

> `requirements.txt` 顶部已明确写有“此文件已弃用，请使用 pyproject.toml”。`requirements-lock.txt` 是历史锁定依赖清单，如需完全复现旧环境才使用；日常 v1.0.1 开发和启动请优先使用 `uv pip install -e .`。

### 5.4 启动后端

保持虚拟环境激活，在一个终端执行：

```bash
# 与 v1.0.1 使用手册一致的入口
python -m app.main

# 项目包入口（功能等价，推荐用于当前仓库）
python -m app
```

后端默认监听 `0.0.0.0:8000`，具体地址和调试模式读取 `.env` 中的 `HOST`、`PORT`、`DEBUG`。

仓库还提供了脚本入口：

- Windows：`scripts\startup\start_backend.bat`
- macOS/Linux：`scripts/startup/start_backend.sh`

> 脚本入口主要用于兼容历史开发流程；如果脚本所在目录导致导入路径异常，直接在项目根目录执行 `python -m app.main` 或 `python -m app`。

### 5.5 启动前端

在另一个终端执行：

```bash
cd frontend
npm install
npm run dev
```

Vite 默认监听 `0.0.0.0:3000`，并将 `/api` 请求代理到 `http://localhost:8000`。浏览器访问 http://localhost:3000。

## 六、启动后首次使用（依据 v1.0.1 使用手册）

无论使用 Docker Compose 还是源码开发模式，服务启动并打开前端后，建议按以下顺序完成首次配置：

1. 登录系统，确认账号认证正常。
2. 进入 **配置管理**，配置厂家信息并确认启用状态。
3. 导入或维护模型目录。
4. 配置要使用的大模型（API Key、Base URL、模型和启用状态）。
5. 配置数据源，例如 AKShare、Tushare 或 FinnHub；需要密钥的数据源请先在 `.env` 或配置页面中完成设置。
6. 打开一只股票，执行一次单股同步测试。
7. 检查同步结果中的主链路、回退链路、错误原因以及 `market_quotes` 写入状态。

`v1.0.1` 新增或强化了 AiHubMix 聚合厂家、模型目录置顶、页面切换刷新和 AKShare 多级回退。修改厂家、模型或后端配置后，请重启后端并刷新前端页面，确保接口返回的是新配置。

## 七、常用检查命令

### Windows PowerShell

```powershell
docker compose ps
Test-NetConnection localhost -Port 3000
Test-NetConnection localhost -Port 8000
Invoke-WebRequest http://localhost:8000/api/health
```

### macOS/Linux

```bash
docker compose ps
curl http://localhost:8000/api/health
curl -I http://localhost:3000
```

端口被占用时：

- Windows：`netstat -ano | findstr :3000` 或 `netstat -ano | findstr :8000`
- macOS/Linux：`lsof -i :3000` 或 `lsof -i :8000`

## 九、启动失败排查顺序

1. 确认 Docker Desktop 或 Docker Engine 正在运行。
2. 确认 `.env` 存在，并且至少配置了 `JWT_SECRET` 和一个模型 API Key。
3. 执行 `docker compose ps`，检查数据库和缓存是否健康。
4. 查看 `docker compose logs backend` 和 `docker compose logs frontend`。
5. 检查 3000、8000、27017、6379 是否被其他程序占用。
6. 首次启动或依赖变更后重新执行 `docker compose up -d --build`。
