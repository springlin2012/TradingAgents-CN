# TradingAgents-CN v1.0.1 启动方式

> 适用版本：`v1.0.1`  
> 更新日期：2026-08-27  
> 适用系统：Windows、macOS、Linux

本文档以仓库当前代码和根目录 `docker-compose.yml` 为准，整理完整服务、源码开发和旧版 Web 界面的启动方式。

## 一、当前服务架构与端口

当前主架构为 FastAPI 后端 + Vue 3 前端，MongoDB 和 Redis 作为基础服务：

| 服务 | Compose 服务名 | 主机端口 | 用途 |
| --- | --- | ---: | --- |
| Vue 前端 | `frontend` | `3000` | 浏览器访问入口 |
| FastAPI 后端 | `backend` | `8000` | REST API、SSE、WebSocket |
| MongoDB | `mongodb` | `27017` | 数据存储 |
| Redis | `redis` | `6379` | 缓存、队列和会话 |
| Redis Commander（可选） | `redis-commander` | `8081` | Redis 管理界面 |
| Mongo Express（可选） | `mongo-express` | `8082` | MongoDB 管理界面 |

启动后访问：

- 前端：http://localhost:3000
- 后端健康检查：http://localhost:8000/api/health
- API 文档（开发模式）：http://localhost:8000/docs

## 二、启动前准备

### 2.1 通用要求

- Docker Desktop（Windows、macOS）或 Docker Engine + Compose 插件（Linux）。
- Python 3.10 或更高版本（源码开发模式需要）。
- Node.js 18 或更高版本、npm 8 或更高版本（前端源码开发需要）。
- 至少一个大模型 API Key，例如 `DEEPSEEK_API_KEY` 或 `DASHSCOPE_API_KEY`。

### 2.2 创建并编辑 `.env`

Windows PowerShell：

```powershell
cd D:\workSpace\TradingAgents-CN
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

macOS/Linux：

```bash
cd /path/to/TradingAgents-CN
if [ ! -f .env ]; then cp .env.example .env; fi
nano .env
```

至少确认以下配置已填写并使用安全值：

```env
JWT_SECRET=请替换为随机字符串
DEEPSEEK_API_KEY=你的API密钥
```

如果使用其他模型提供商，可改为配置 `DASHSCOPE_API_KEY`、`OPENAI_API_KEY` 等。不要把真实密钥提交到 Git。

## 三、Docker Compose 启动（推荐）

Docker 方式适合 Windows、macOS 和 Linux，三种系统使用同一套 Compose 配置。

### 3.1 检查 Docker

```bash
docker --version
docker compose version
```

Windows 用户需要先启动 Docker Desktop；Linux 用户需要确保 Docker 服务已启动并且当前用户有执行 Docker 的权限。

### 3.2 首次启动或代码变更后

Windows PowerShell、macOS、Linux 均可执行：

```bash
docker compose up -d --build
```

该命令会构建后端和前端镜像，并启动 MongoDB、Redis 及应用服务。首次构建可能需要数分钟。

### 3.3 日常启动

镜像已构建且没有修改代码或依赖时：

```bash
docker compose up -d
```

### 3.4 查看状态与日志

```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
```

浏览器打开 http://localhost:3000；如果页面无法访问，先确认 `backend`、`frontend`、`mongodb`、`redis` 均处于 `Up` 或健康状态。

### 3.5 启用可选管理界面

```bash
docker compose --profile management up -d
```

然后访问：

- Redis Commander：http://localhost:8081
- Mongo Express：http://localhost:8082

### 3.6 停止或重启

```bash
# 停止容器但保留容器和数据卷
docker compose stop

# 重新启动
docker compose restart
```

## 四、源码开发模式

源码开发模式需要本机安装 Python 和 Node.js，MongoDB、Redis 可以继续使用 Docker 启动。

### 4.1 启动 MongoDB 和 Redis

在项目根目录执行（Windows、macOS、Linux 相同）：

```bash
docker compose up -d mongodb redis
```

### 4.2 创建 Python 虚拟环境

Windows PowerShell：

```powershell
cd D:\workSpace\TradingAgents-CN
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

如果 PowerShell 阻止脚本执行，可仅对当前窗口放宽策略：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

Windows 命令提示符（cmd）：

```bat
cd /d D:\workSpace\TradingAgents-CN
py -3.10 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
```

macOS/Linux：

```bash
cd /path/to/TradingAgents-CN
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 4.3 启动后端

保持虚拟环境激活，在一个终端执行：

```bash
python -m app
```

后端默认监听 `0.0.0.0:8000`，具体地址和调试模式读取 `.env` 中的 `HOST`、`PORT`、`DEBUG`。

也可以使用系统提供的启动脚本：

- Windows：`scripts\startup\start_backend.bat`
- macOS/Linux：`scripts/startup/start_backend.sh`

### 4.4 启动前端

在另一个终端执行：

```bash
cd frontend
npm install
npm run dev
```

Vite 默认监听 `0.0.0.0:3000`，并将 `/api` 请求代理到 `http://localhost:8000`。浏览器访问 http://localhost:3000。

## 五、旧版 Streamlit Web 界面（过时）

仓库仍保留旧版 Streamlit 界面，适合兼容历史使用场景，不作为 v1.0.1 主架构启动方式。该界面使用 8501 端口，与当前 Vue 前端的 3000 端口不同。

Windows、macOS、Linux：

```bash
python web/run_web.py
```

访问 http://localhost:8501。

> **注意**：`scripts/start_docker.ps1`、`scripts/start_docker.sh` 以及部分旧版 Docker 文档仍检查 8501 或 `web` 容器，它们属于历史启动流程。使用 v1.0.1 时请优先执行本文件第三节的 `docker compose` 命令。

## 六、常用检查命令

### Windows PowerShell

```powershell
docker compose ps
Test-NetConnection localhost -Port 3000
Test-NetConnection localhost -Port 8000
Invoke-WebRequest http://localhost:8000/api/health
```

### macOS/Linux

```bash
docker compose ps
curl http://localhost:8000/api/health
curl -I http://localhost:3000
```

端口被占用时：

- Windows：`netstat -ano | findstr :3000` 或 `netstat -ano | findstr :8000`
- macOS/Linux：`lsof -i :3000` 或 `lsof -i :8000`

## 七、启动失败排查顺序

1. 确认 Docker Desktop 或 Docker Engine 正在运行。
2. 确认 `.env` 存在，并且至少配置了 `JWT_SECRET` 和一个模型 API Key。
3. 执行 `docker compose ps`，检查数据库和缓存是否健康。
4. 查看 `docker compose logs backend` 和 `docker compose logs frontend`。
5. 检查 3000、8000、27017、6379 是否被其他程序占用。
6. 首次启动或依赖变更后重新执行 `docker compose up -d --build`。
